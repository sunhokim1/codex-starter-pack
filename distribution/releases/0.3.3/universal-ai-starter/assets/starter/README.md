# Universal AI Development Starter

프레임워크 중립 프로젝트 운영 템플릿, 버전 0.3.3. 앱·기술 스택·검증 명령은 아직 초기화되지 않았습니다. 실제 프로젝트 파일과 사용자 요구를 확인한 뒤 설정하세요.

## 핵심 파일

| 파일 | 용도 |
| --- | --- |
| AGENTS.md | 작업·보존·검증 기준과 실제 subsystem map |
| PROJECT.md | 확인한 프로젝트 목표·스택·실행 환경·제약 |
| .ai/models.yaml | 사용자가 선택한 역할별 모델 ID |
| .ai/routing.yaml | 단일 모델 선택·reasoning·순차 승격 지침 |
| .ai/verification.yaml | 실제 존재하는 명령만 설정; 초기값은 null |
| .ai/config.yaml | 선택 기능 상태; true만으로 기능이 구현되지는 않음 |
| .gitignore | 로컬 workflow·설치 경로·보고서·비밀 파일 제외 |

새 프로젝트에는 다른 앱의 사실이나 테스트 명령을 넣지 않습니다. 기존 프로젝트의 사실·모델·명령·문서는 보존합니다. 초기화와 실제 검증 실행·통과는 별개입니다.

## 적용

배포 ZIP은 `universal-ai-starter/SKILL.md`가 개인 스킬 폴더 안에 위치하도록 풀어 사용합니다. 설치 스크립트를 원격 main 브랜치에서 즉시 실행하는 방식은 안내하지 않습니다. 신뢰한 배포 출처와 ZIP digest를 확인하세요. ZIP 안 manifest는 내부 일관성 검사이며 서명이 아닙니다.

스킬 적용은 `scripts/scaffold.py --target <project> --dry-run`으로 먼저 확인합니다. 일반 실행은 핵심 파일 복사 후 SEV 설치를 진행합니다. `--adopt`는 기존 일반 파일을 보존하고 없는 파일만 추가합니다. `--files-only`는 SEV를 설치하지 않는 명시적인 파일 적용 모드입니다. `--no-autostart`는 로그인 시작 등록을 생략합니다. 설치 실패 시 새로 복사된 핵심 파일은 남고 기존 파일은 보존되므로 결과를 확인한 후 설치 단계만 재시도하세요.

SEV 설치에는 Python 3.11+, 인터넷과 디스크 공간이 필요합니다. 코딩 실행에는 Codex CLI와 사용 가능한 계정·모델이 필요합니다. 설치기는 인증 설정을 바꾸지 않습니다.

## 실행·검증

SEV 설치 후 `.ai/sev.json`의 경로를 사용합니다. 설치된 지침은 일반 질문과 개발 요청을 구분하며 큰 작업은 순차 controller를 사용합니다. 앱 대화 모델은 바뀌지 않습니다. 사용자 모델 override가 우선하고, SEV 실패 시 유료 분류로 자동 대체하지 않습니다.

quick runner는 관련 설정 검증이 실제 통과해야 completed가 됩니다. 미실행·누락·실패·모든 명령 null은 완료가 아닙니다. controller 소유 모드의 모델 결과는 awaiting_verification이며, controller가 실제 검증 후 최종 완료를 판정합니다. quick의 검증 근거는 여전히 모델 보고이며 별도 관측이라고 주장하지 않습니다.

큰 작업은 한 목표·계획·순차 작업·검증·상태 저장의 유한 실행입니다. 기본 호출/시간 한도, 승인·실패·재시도 조건을 지킵니다. 백그라운드 자동 개선이나 모델 자가학습을 시작하지 않습니다.

## 보존과 기록

설치기는 기존 공용 런타임을 중지하거나 덮어쓰지 않고 버전별 새 배포를 준비해 서비스 준비 상태를 확인합니다. 성공한 프로젝트만 새 경로를 가리킵니다. 기존 개인 스킬은 보존하며, 새로 필요한 지침 파일만 추가합니다. 설치 실패 시 프로젝트 문서·설정을 복원하고 새 서비스만 종료를 시도합니다. 복원·종료 실패는 명시적으로 보고합니다. 이전 배포와 실패한 준비 디렉터리는 자동 삭제하지 않으므로 점검 후 수동 정리하세요. 버전이 공존하는 동안 서비스와 모델 메모리도 중복될 수 있습니다.

비밀값은 요청문에 붙여넣지 말고 환경변수·비밀 저장소 참조로 전달하세요. 알려진 키·password/token 할당·Bearer·개인키 형식은 실행 입력과 저장 보고서에서 마스킹합니다. 이 때문에 문자 그대로의 비밀값을 필요로 하는 작업은 환경 참조로 다시 작성해야 합니다. 일반 문장 속 임의의 비밀을 완벽하게 찾는 기능은 아닙니다.

선택 입력은 해시와 길이만 보고서에 남깁니다. 콘솔은 상태 요약만 출력하고 workflow 상태·goal/facts·검증 출력 전체를 출력하지 않습니다. 재개를 위한 상태에는 마스킹된 작업 내용이 포함됩니다. 개인 파일은 임시 파일의 현재 사용자 권한을 설정한 후 기록하고 원자적으로 교체합니다. Windows 권한 설정 실패는 쓰기를 중단합니다. 보고서는 `.ai/reports/` 안에 두고 보관 기간은 프로젝트 필요에 맞춰 정하세요. Git ignore는 이미 추적 중인 파일을 제거하지 않으므로 기존 기록은 별도 점검이 필요합니다.

SEV는 로컬 분류기이며 분류 점수는 코딩 성공률이나 비용 절감 증거가 아닙니다. 생성된 프로젝트의 스택을 임의로 설치하거나 기존 검증 명령을 템플릿 기본값으로 바꾸지 않습니다.

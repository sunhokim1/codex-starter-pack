# 0.3.1 수정 내역

2026-10-19. 사용자 제공 0.3.0 ZIP을 기준으로 별도 수정본을 만들었습니다. 원본 ZIP과 기존 설치·프로젝트는 변경하지 않았습니다. 모델 매핑과 후보 NPZ 가중치도 유지했습니다.

## 수정한 내용

| 영역 | 변경 |
| --- | --- |
| 범용 템플릿 | 다른 게임 프로젝트의 사실·없는 경로·없는 테스트 명령 제거. PROJECT와 검증은 미초기화 상태. 기존 파일 adopt 보존 |
| 완료 판정 | quick의 미실행·누락·실패·모든 명령 null은 completed 불가. controller 모드는 awaiting_verification을 반환하고 실제 검사 후에만 최종 완료 |
| SEV 입력 | JSON 최상위 객체, 인증 token, op, 문자열 타입, 허용 필드·크기 검사. 오류 연결 뒤 정상 요청을 계속 처리 |

## 실제 검증

40개 오프라인 회귀 검사로 동작을 확인합니다. 최종 실행 결과는 수정 ZIP과 함께 제공하는 `universal-ai-starter-0.3.1-tests.txt`에 있습니다. Python 구문, 템플릿 생성·채택·충돌, quick/controller 완료 판정, SEV 잘못된 요청 뒤 생존, 설치 실패 복원·기존 런타임/스킬 보존, 마스킹·개인 파일 쓰기·Windows ACL 명령 구성과 배포 무결성을 포함합니다.

실제 설치·모델 다운로드·Codex 유료 호출·서비스 소켓·Windows ACL 적용은 모형으로 대체했습니다. Windows Python 3.14 환경에서 실행했으며 Python 3.11, 실제 설치·추론·시작 항목·ACL의 최종 동작은 별도 격리 환경에서 확인해야 합니다. 회귀 검사 통과를 이 통합 검증의 통과로 주장하지 않습니다.

수정 ZIP은 새 manifest로 재빌드하고, 다시 압축을 풀어 파일 집합·해시와 회귀 검사를 확인합니다. 기본 명령은 다음과 같습니다.

```text
python -m unittest discover -s tests -p "test_*.py" -v
python scripts/package_starter.py --check
```

## 적용·호환성

0.3.0 ZIP을 지우거나 기존 프로젝트를 다시 만들 필요는 없습니다. 새 배포 폴더에서 dry-run 후 적용하세요. `--files-only`는 파일만 적용하며, SEV 설치까지 진행할 경우 옵션을 생략합니다. 기존 프로젝트는 `--adopt`로 기존 핵심 파일을 보존합니다. 이미 존재하는 오염된 PROJECT/AGENTS는 자동 삭제·초기화하지 않으므로 실제 프로젝트 사실을 확인하고 수동 병합해야 합니다.

기존 핵심 파일을 준비한 프로젝트에는 새 `install_sev.py --target <project>`로 명시적으로 연결합니다. 개인 스킬 지침은 보존되므로 사용자 커스터마이징을 유지합니다. 실행 코드 경로는 새 `.ai/sev.json`을 읽습니다. 기존 지침이 오래되어 새 동작을 설명하지 않으면 비교 후 필요한 부분만 병합하세요.

기존 프로젝트는 연결하기 전까지 이전 버전 경로를 사용합니다. 이전 배포·실패 배포·기존 로그인 시작 항목은 자동 삭제하지 않습니다. 이로 인해 여러 버전 서비스가 공존할 수 있으며, 모든 연결 프로젝트와 시작 항목을 점검한 뒤 더 이상 사용하지 않는 버전만 수동 정리해야 합니다.

quick 완료 조건이 엄격해져 이전에는 완료로 보이던 미검증 작업이 unresolved가 될 수 있습니다. controller와 quick runner는 같은 버전 폴더의 조합으로 사용하세요. 기존 state schema 2는 유지하지만 새 SEV 설정으로 바뀌면 기존 controller의 설정 hash 규칙에 따라 중단·정리 후 새 목표로 시작해야 합니다. 저장된 hash를 고쳐 강제 재개하지 않습니다.

## 남은 한계

- 단일 모델 quick의 검사 결과는 모델 보고입니다. controller의 실제 subprocess 관측과 구분합니다.
- 자격증명 마스킹은 알려진 형식에 대한 보조 장치이며 임의의 문장 속 모든 비밀·개인정보를 찾지 못합니다. 비밀은 요청문 대신 환경/저장소 참조로 전달하세요. 원문 그대로의 비밀이 필요한 작업은 환경 참조로 바꿔야 합니다.
- Git 제외는 이미 추적된 파일과 과거 커밋을 제거하지 않습니다. 기존 로그·Git 이력·실행 환경의 비밀 관리는 별도입니다.
- 설치 복원은 처리 가능한 예외·인터럽트에 대한 것입니다. 강제 종료·전원 장애에 걸친 다중 파일 commit의 durable journal/recovery는 다음 작업입니다. 복원 실패가 발생하면 자동 재시도하지 말고 보고된 배포와 프로젝트 파일을 점검하세요.
- 자손 프로세스 전체 종료, 재개 시 완료 의존성 파일 변경 검출, 설정 schema 통합은 후속 backlog에 남아 있습니다.
- 분류기의 실제 비용/성공률 benchmark와 학습 데이터 검증은 수행하지 않았습니다. 성능 개선을 주장하지 않습니다.
- 일부 오래된 실험용 Selector 진입점은 별도 index/calibrated 자산이 필요합니다. 실제 service 경로인 KeywordSelector + LongCandidate를 사용하세요.

이 수정본은 자기개선 스케줄러를 설치하거나 백그라운드 작업을 시작하지 않습니다. 다음 변경은 `CONTINUOUS_IMPROVEMENT.md`의 한 회차 절차로 진행합니다.

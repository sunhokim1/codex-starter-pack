# 소스 업데이트와 기존 실행 연결의 명시적 이전

관리기와 기본 PowerShell/`--source-only`는 소스·클라이언트만 자동 설치·업데이트합니다. 기존 완료 상태와 설정은 보존하며 활성·불확실한 상태만 개별 검토를 위해 중단합니다. 모델·서비스·환경 lock·연결이 없어도 소스 설치는 가능합니다. 아래 번호 절차는 실행 연결을 별도로 이전할 때의 안내입니다. 개발 과정에서는 실제 프로젝트 연결을 변경하지 않습니다.

1. 기존 runtime으로 status와 전체 보고서를 읽고 완료 작업·불확실한 편집을 점검합니다. `.ai/project-workflow/state.json` 또는 `.ai/rev-workflow/state.json`이 존재하면 설치기는 중단합니다. 프로젝트 밖 안전한 위치에 보고서와 상태를 명시적으로 보관하고 진행 중 작업을 정리하세요. 원래 파일을 자동 이전·삭제하거나 완료 작업을 재생하지 않습니다.
2. `python scripts/install_rev.py --target <project> --plan`으로 연결·상태·참조 범위를 확인합니다. `reference_report([project_roots], legacy_runtime)`은 지정한 루트만 확인하고 `exhaustive=false`, `deletion_allowed=false`를 반환합니다. 전역 미사용을 증명하지 않습니다. 공유 SEV 설치를 삭제하지 마세요.
3. `python scripts/scaffold.py --target <project> --adopt --files-only`는 검증 소스·클라이언트를 `.ai/starter-source/`에 설치·업데이트하고 누락 템플릿만 추가합니다. 기존 실행 연결은 바꾸지 않습니다. 기존 `PROJECT.md`, README, 지침과 모델·routing·검증 설정은 보존됩니다. 실제 설정을 검토해 새 schema에 맞춰 별도로 조정하세요. `planning_model: gpt-6.1-sol`, `execution_model: null`은 기본 Rev 선택입니다. 사용자 override는 유지하며 임의로 null로 바꾸지 마세요. 검증 명령도 실제 프로젝트 값을 유지하세요. 구 routing 규칙은 자동 변환하지 않고 중단합니다.
4. 선택한 CPU/CUDA 모드의 메모리와 실제 의존성 capability를 확인한 장비에 검증된 source/checkpoint/base와 완성한 environment lock을 먼저 준비하고 인증 loopback 서비스를 시작합니다. 연결 JSON은 `contracts/examples.json`의 connection 형식을 따르며 token 값 대신 `token_env`를 참조합니다. `/ping` readiness와 lock identity가 일치해야 합니다. Windows·CPU를 일괄 거부하지 않습니다. `--device cpu --dtype fp32` 또는 `--device cuda:N --dtype bf16|fp16|fp32`를 별도로 선택하고 자원·kernel·warmup을 확인합니다. Intel Iris Xe는 CUDA가 아니며 XPU 지원도 확립하지 않았습니다. 원격 비인증 endpoint는 거부합니다.
5. `python scripts/install_rev.py --target <project> --runtime-root <new-isolated-directory> --connection-file <reviewed-json> --migrate`를 명시적으로 실행합니다. runtime은 기존 경로와 겹치면 안 됩니다. 새 `.ai/rev.json`과 `.ai/rev-install.json`을 만들고 AGENTS의 완전한 기존 `starter-sev` 관리 블록만 `starter-rev`로 교체합니다. 블록 밖 문구는 보존하며 모호한 표식은 중단합니다. `.gitignore`에는 새 private 관리 블록만 추가합니다. 기존 `.ai/sev.json`·설정·개인 skills·공유 SEV는 유지합니다. 실패 시 이번에 만든 파일과 runtime만 복구합니다. 기존 Rev 연결도 자동 덮어쓰지 않습니다.

PowerShell 진입점은 `scripts/install_from_github.ps1 -Target <project> -BundlePath <reviewed-bundle> -FilesOnly` 또는 명시적 `-RuntimeRoot`, `-ConnectionFile`, 필요 시 `-Migrate`를 받습니다. 검토한 `-ArchivePath`도 가능합니다. 기본 입력은 main을 한 번 조회하고 immutable commit으로 고정해 다운로드합니다. 공개 main에 0.4.0이 없으면 안전하게 실패하며 기존 설치를 보존합니다. 공개 0.4.0 게시 자체는 이 작업 범위 밖입니다. 향후 immutable `-SnapshotCommit`이 제공될 때 해당 commit의 0.4.0 ZIP과 metadata 전체가 일치해야 합니다. 개인 skill 교체와 자동시작 등록은 수행하지 않습니다.

관리기 앱 로컬 0.2.0은 신규·SEV·Rev 프로젝트에 소스·클라이언트를 자동 설치·업데이트합니다. `.ai/source-install.json`은 별도 소스 영수증이며 기존 실행 연결·사용자 지침·설정·완료 기록을 덮어쓰지 않습니다. 수정된 관리 파일, 활성·불확실한 workflow, 모호한 journal은 개별 검토가 필요합니다. higher source version은 낮추지 않습니다. 설치 성공은 Rev 서비스 readiness나 실제 추론 성공을 뜻하지 않습니다. `python -B scripts/install_rev.py --target <project> --source-only` 또는 PowerShell 기본 실행은 소스 작업이며 하드웨어·모델 lock·서비스를 요구하지 않습니다. 명시적 연결 작업에만 위 이전 절차의 환경·상태 검토가 필요합니다.

최종 0.4.0 controller는 schema=3입니다. 이전 개발본 schema=1/2도 status만 읽고 자동 재개·변환하지 않습니다. 원래 runtime의 전체 보고서·완료 결과를 보존하고 명시적으로 정리·보관해야 하며, 새 계획이 완료 작업을 반복하게 해서는 안 됩니다. 새 배포 예시의 `routing.recovery`를 검토할 수 있지만 기존 설정을 자동 교체하지 않습니다. 이 개발 작업에서는 기존 설치·연결·개인 runtime을 변경하지 않았습니다.
